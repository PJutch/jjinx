# Документация Jjinx

## Сборка
```bash
cargo build --release
```

## Использование
```bash
jjinx --config your-config.conf
```

## Протоколы
Поддерживает HTTP/1.1 и HTTPS

# Конфигурация
jjinx использует nginx-подобный формат конфигов с рядом отличий

## Пример конфигурации
```
upstream backend {
    round_robin
    server app1.example.com
    server app2.example.com
}

server {
    port 8080
    default

    route = / {
        redirect /index.html
    }

    route /index.html {
        file index.html
    }

    route /get-host {
        body "Host: $host\n"
    }

    route /simple-proxy {
        proxy http://app.example.com:80
    }

    route /upstream-proxy/ {
        proxy http://backend:8000
    }

    route /404 {
        body "Not found"
    }

    error_page 404 /404
}

server {
    port 4433
    default

    ssl_cert server.crt
    ssl_keys server.key

    route / {
        proxy http://localhost:8080
    }
}

```

## server { ... }
Аналогично директиве server в nginx, задаёт параметры для порта+ip+доменного имени.
Для каждой комбинации ip+порт создаётся свой tokio task, который принимает входящие соединение

### port &lt;port&gt;
Задаёт порт, по умолчанию 8080

### ip &lt;ip&gt;
Задаёт ip, по умолчанию не указан

### domain &lt;domains...&gt;
Задаёт доменное имя.
Может быть несколько для одного сервера

### default
Помечает сервер как сервер по умолчанию (если ни одно доменное имя не совпало).
Изначально сервер по умолчанию - первый с данным ip и port

### error_page &lt;error codes...&gt; &lt;route&gt;
Возвращает содержимое с данного пути для ошибки с соответсвубщим кодом.
Ручка для данного пути ищется как при обычном запросе.
Не применяется если ошибка указана с помощью директивы status.

### ssl_cert &lt;path&gt;
Задаёт путь до ssl-сертификата.
Присутсвие включает https и требует наличия ssl_keys

### ssl_keys &lt;path&gt;
Задаёт путь до приватного ключа для ssl-сертификата.
Присутсвие включает https и требует наличия ssl_cert

### header_timeout &lt;timeout&gt;
Задаёт таймаут на получение первой строки/заголовков запроса (в секундах)

### body_timeout &lt;timeout&gt;
Задаёт таймаут на получение пакета тела запроса (в секундах)

### send_timeout &lt;timeout&gt;
Задаёт таймаут на отправку ответа (в секундах)

## route [matcher] &lt;path&gt; { ... }
Задаёт ответ для заданного пути uri

matcher может принимать значение
- по умолчанию - подходит, если path - префикс пути из запроса
- ~ - сравнивает с регулярным выражением
- ~* - сравнивает с регулярным выражением без чувствительности к регистру
- ^~ - как по умолчанию, но имеет приоритет над префикс
- = - проверяет на точное совпадение

Приоритет = > ^~ > ~ и ~* > (по умолчанию)

При совпадении с несколькими
Для префиксов выбирается длиннейший
Для регулярных выражений - первое объявленное

### status
Задаёт код возврата

### header &lt;header_name&gt; &lt;value&gt;
Задаёт HTTP заголовок

### file &lt;files...&gt;
Возвращает содержимое файла.
Если файлов несколько, используется первый существующий.
Если matcher префиксный, то остаток пути из запроса приписывается к указанному здесь
Если указана папка, пытается найти в ней index.html

### body &lt;content&gt;
Возвращает фиксированную строку

### redirect &lt;uri&gt;
Перенаправление (задаёт заголовок Location и статус 308 или из status)

### proxy &lt;uri&gt;
Отправляет копию запроса по заданному uri и возвращает ответ.
Вместо доменного имени можно указать upstream.
Если в uri есть путь и matcher префиксный, то остаток пути из запроса приписывается к указанному в uri.

### proxy_header &lt;header_name&gt; &lt;value&gt;
Задаёт HTTP заголовок для запроса к upstream

### default_content_type &lt;content_type&lt;
Задаёт Content-Type если его не удалось определить по расширению файла

## upstream { ... }
Задаёт набор серверов, которым можно перенапралять запрос

### server &lt;uri&gt;
Добавляет сервер в набор

### round_robin
Задаёт round robin распределение нагрузки

### least_conn
Отправляет запрос к серверу с наименьшим кол-вом соединений

### ip_hash
Выбирает сервер по хэшу ip клиента

### connect_timeout &lt;timeout&gt;
Задаёт таймоут на подключение к upstream (в секундах)

### send_timeout &lt;timeout&gt;
Задаёт таймоут на отправку запроса к upstream (в секундах)

### header_timeout &lt;timeout&gt;
Задаёт таймоут на получение заголовка от upstream (в секундах)

### body_timeout &lt;timeout&gt;
Задаёт таймоут на получение тела запроса от upstream (в секундах)

### max_fails &lt;max_fails&gt;
Если кол-во неудачных запросов к серверу в upstream за последние fail_timeout секунд > max_fails,
соответсвующий сервер не будет использован для запросов

### fail_timeout &lt;fail_timeout&gt;
Длина окна, в котором считаются неудачные запросы (в секундах)

## Переменные
jjinx может заменять переменные вида $&lt;name&gt; (как строку)

### set &lt;name&gt; &lt;value&gt;
Создаёт переменную в данном блоке с фигурными скобками / на верхнем уровне.
В отличии от других, эти переменные подставляются при парсинге конфигурации

### $uri
Uri запроса

### $host
Заголовок host / host из uri

### $method
Метод запроса

### $http_&lt;header&gt;
Значение заголовка запроса

### $env_&lt;variable&gt;
Значение переменной окружения
